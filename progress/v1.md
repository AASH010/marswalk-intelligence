# 1. Executive Summary — الملخص التنفيذي

نعمل على دمج بيانات الطقس الصادرة عن جهاز **MEDA (Mars Environmental Dynamics Analyzer)** الموجود على مركبة Perseverance ضمن مشروع MarsWalk Intelligence.

الهدف ليس مجرد عرض درجات الحرارة وسرعة الرياح، بل تجهيز مصدر بيانات علمي يمكن الاعتماد عليه في:

1. بناء Unified Weather Profile يمثل الظروف الجوية المستخلصة من قياسات MEDA.
2. إجراء Mission Weather Analysis لتقييم الظروف الجوية وتأثيرها على أنشطة المهمة.
3. دعم تقدير استهلاك الموارد، مثل الطاقة والمياه والوقت، عند الحاجة.
4. تطوير Spatial Weather Cost Model لاستخدامه في حساب تكلفة الطقس داخل خوارزمية A*، بشرط وجود نموذج مكاني مبرر علميًا.
5. إظهار المعلومات والنتائج في واجهة MWI من خلال Backend APIs وFrontend Dashboard.

## الحالة الحالية

وصلنا إلى مرحلة متقدمة في تجهيز البيانات وفحص بنيتها:

- تنزيل وتجهيز مجموعة بيانات MEDA.
- بناء Normalized JSONL Dataset.
- تحويل سجلات المنتجات المختلفة إلى Records موحدة.
- إجراء Structural QA على كامل البيانات.
- اكتشاف Schema الفعلي للبيانات.
- إجراء Variable-Level QA على 41 متغيرًا.
- إصلاح مشكلة حساب Missing Variables في تقرير V2.
- مراجعة التغطية الإحصائية والنتائج الأولية لكل متغير.

**ما لم يكتمل بعد:** التحقق العلمي من القياسات والـ Quality Flags، اعتماد المتغيرات النهائية، بناء Aggregation، تطوير Weather Service وAPIs، التكامل مع A* والواجهة، ثم الاختبار النهائي.

بالتالي، نحن حاليًا في مرحلة **Data Preparation & Quality Assessment**، ولسه لم نصل إلى مرحلة Weather Service Integration.

# 2. الهدف النهائي من المهمة

المهمة النهائية مقسمة إلى ثلاث طبقات مترابطة، ويجب عدم الخلط بينها.

## 2.1 Unified Weather Profile

الطبقة الأولى هي تكوين ملف جوي موحد اعتمادًا على القياسات الفعلية التي جمعها MEDA.

المفترض أن يحتوي على معلومات مثل:

- Air Temperature.
- Ground Brightness Temperature.
- Atmospheric Pressure.
- Relative Humidity.
- Wind Speed.
- Wind Direction.
- Solar Irradiance.
- Solar Zenith Angle.
- بيانات زمنية وإحصائية مساعدة.

هذا الملف لا يعني أن كل القيم تمثل قياسًا لحظيًا واحدًا؛ بل يجب الاحتفاظ بالمعلومات الزمنية ومصادر القياسات والتغطية الخاصة بكل متغير.

## 2.2 Mission Weather Analysis

الطبقة الثانية تستخدم الـ Weather Profile لتقييم الظروف الجوية وتأثيرها على المهمة.

يمكن أن تشمل:

- تقييم الظروف الجوية خلال فترة زمنية معينة.
- تحديد الظروف غير المعتادة.
- تحليل تأثير درجة الحرارة والرياح والإشعاع على الأنشطة.
- دعم تقديرات الموارد والقيود التشغيلية.
- إنتاج Weather Severity أو Mission Weather Assessment عند وجود منهجية ومعايير موثقة.

يجب ألا نضع حدودًا علمية من عندنا. أي Threshold يجب أن يكون مستندًا إلى مصدر علمي أو موثقًا بوضوح باعتباره Assumption.

## 2.3 Spatial Weather Cost

الطبقة الثالثة مرتبطة بخوارزمية A*.

الهدف هو تقدير تأثير الظروف الجوية على الحركة عبر الخريطة.

المعادلة التصميمية المقترحة:

\[
C_{\text{total}}(x,y)
=
C_{\text{terrain}}(x,y)
+
\lambda C_{\text{weather}}(x,y)
\]

حيث:

- \(C_{\text{terrain}}\): تكلفة التضاريس.
- \(C_{\text{weather}}\): تكلفة الطقس المقدرة مكانيًا.
- \(\lambda\): معامل وزن تأثير الطقس.

**قيد علمي أساسي:**

MEDA جهاز قياس جوي موجود على المركبة، وليس Weather Raster Sensor يغطي كل خلية في الخريطة.

لذلك لا يجوز وصف كل خلية على أنها تحتوي على قياس طقس حقيقي.

إذا أنشأنا Weather Cost لكل خلية، فيجب أن يكون ناتج Spatial Exposure Model واضح الافتراضات ومصدر البيانات، ويُعرض باعتباره تقديرًا مكانيًا وليس قياسًا مباشرًا.

# 6. خطة العمل المتبقية حتى اكتمال المهمة

## Phase 1 — Scientific Validation & Variable Classification

**الهدف:** تحديد أي القياسات يمكن الوثوق بها واستخدامها.

### Task 1.1 — Quality Flag Mapping

دراسة توثيق المنتجات الأصلية وربط Quality Flags بالمتغيرات.

أمثلة:

- `quality.WS.BOOM1_ALG_STATE_STABLE`
- `quality.WS.BOOM2_ALG_STATE_STABLE`
- `quality.WS.ROVER_STILL`
- Quality fields الخاصة بمنتجات الضغط والحرارة والرطوبة.

المطلوب:

1. تحديد معنى كل Flag.
2. تحديد القيم المسموح بها.
3. تحديد ما إذا كان Flag يدل على الاستقرار أو صلاحية القياس أو حالة الجهاز.
4. تحديد المتغيرات التي يرتبط بها.
5. توثيق طريقة استخدامه في QA وAggregation.

**Deliverables:**

- MEDA Quality Flag Mapping.
- Quality Interpretation Rules.
- Source Documentation References.

### Task 1.4 — Variable Classification

تصنيف المتغيرات الـ 41 إلى:

**Primary Weather Variables**

المتغيرات الأساسية التي ستدخل في تكوين Weather Profile.

**Supporting Variables**

متغيرات تساعد في تفسير القياسات أو التحقق منها، وقد تستخدم في التحليل.

**Diagnostic / Raw Variables**

قنوات خام أو معلومات تشخيصية لا ينبغي عرضها باعتبارها قياسات جوية نهائية.

**Deferred Variables**

متغيرات لا تزال وحداتها أو تعريفاتها أو صلاحيتها غير محسومة.

### Task 1.5 — Canonical Variable Selection

اختيار المتغير الأساسي الذي يمثل كل خاصية جوية.

مثال:

| Weather Property | Candidate Variables |
|---|---|
| Air Temperature | `air_temp_k` |
| Pressure | `pressure_pa` والقنوات المرتبطة |
| Relative Humidity | Humicap A/B وDerived RH |
| Wind Speed | Boom 1/2 وDerived Horizontal Wind |
| Wind Direction | Boom Directions وDerived Direction |
| Solar Radiation | Upward/Downward Irradiance |

الجدول يمثل المرشحين فقط، وليس قرارات اعتماد نهائية.

**مخرج Phase 1:**

`MEDA_SCIENTIFIC_VALIDATION_REPORT.md`

و:

`MEDA_VARIABLE_CLASSIFICATION.json`

لا ننتقل للمرحلة التالية قبل توثيق قرارات الاعتماد والاستبعاد والتأجيل.

## Phase 3 — Weather Aggregation Engine

**الهدف:** تحويل القياسات المعتمدة إلى إحصائيات قابلة للاستخدام في MWI.

هذه المرحلة ليست مجرد حساب Mean لكل متغير.

### Task 3.1 — Per-Sol Aggregation

إنشاء إحصائيات لكل متغير داخل كل Sol.

مثل:

- Count.
- Valid Count.
- Missing Count.
- Min.
- Max.
- Mean.
- Median.
- Standard Deviation.
- Coverage.
- First / Last Timestamp.

يجب الاحتفاظ بإحصائيات كل Sol بصورة مستقلة.

### Task 3.2 — Global Aggregation

إنشاء إحصائيات موحدة عبر كل الـ Sols.

يجب التفريق بين:

**Pooled Statistics:** تجميع جميع القراءات الصالحة معًا.

**Equal-Sol-Weighted Statistics:** حساب إحصائيات تعطي كل Sol وزنًا متساويًا عندما يكون ذلك مناسبًا للهدف التحليلي.

لا نستبدل أحدهما بالآخر؛ بل نوضح تعريف كل نتيجة.

### Task 3.3 — Circular Statistics

تطبيق Circular Statistics على:

- Wind Direction.
- أي متغير زاوي آخر يحتاج معالجة دورية.

لا نستخدم المتوسط الحسابي الخطي للاتجاهات.

### Task 3.4 — Temporal Aggregation

تحديد كيفية تجميع القياسات عبر الزمن.

يجب ألا ندمج قراءات ذات أزمنة مختلفة في Snapshot واحد دون توضيح.

المطلوب:

- Time Ordering.
- Sampling Intervals.
- Time Window Aggregation.
- Missing Time Intervals.
- Coverage per Time Window.

### Task 3.5 — Aggregation QA

اختبار:

- صحة الأعداد.
- اتساق Per-Sol مع Global.
- التعامل مع القيم غير الصالحة.
- اتساق الوحدات.
- عدم تكرار القياسات.
- صحة Circular Statistics.
- صحة Time Windows.

**Deliverables:**

- Aggregation Module.
- Per-Sol Summary.
- Global Summary.
- Aggregation QA Report.

- A* بدون Weather Cost.

وتحليل تأثير التعديل على:

- Route Selection.

- Weather Exposure Estimate.
